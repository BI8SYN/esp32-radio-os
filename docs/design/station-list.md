## 阶段 1 · 产品定义

一句话：**帮助收音机用户，通过分层电台源（收藏 / 内置精选 / 在线目录）加轻量筛选，快速找到一个能播的电台。**

核心场景（按频率排序）：

1. 开机想马上听常听的台 → 收藏列表，两步内出声
2. 想找点新东西听 → 在线目录按分类翻，点了就播
3. 当前台听腻了 / 流挂了 → 快速换台（上一台 / 下一台）
4. 网络目录服务不可用 → 内置精选列表兜底，保证「开箱有声」

MVP 三功能测试——只留这三个，产品仍成立：

1. 三源列表（收藏 / 精选 / 在线）+ 点击播放
2. 在线目录的分类筛选 + 分页加载
3. 收藏 / 取消收藏，持久化到 NVS

其余全部是增强项，本期**不做**：设备端文本搜索、SD 卡导入电台、Web 配置页、按码率筛选、多选标签、电台台标图片。

## 阶段 2 · User Flow

主场景「找新台」：

```
正在播放页 → 点[电台列表] → 列表页（落在上次使用的 tab；首次启动落在精选）
→ 切到[在线] → Loading（拉 radio-browser 第一页）→ 列表
→ 点[筛选] → 选分类「音乐」→ [应用] → Loading → 筛选后列表
→ 点某个台 → 回正在播放页（缓冲中…）→ 出声 → （可选）点 + 收藏
```

逐步审视：

- **删**：首次启动直接落在精选而非空收藏，删掉一次「怎么是空的」的犹豫
- **自动**：tab 记忆上次选择（NVS）；筛选应用后自动返回列表并刷新，不需要再点返回
- **合并**：点台 = 选台 + 播放，一步；不设「先选中再确认」
- **犹豫点**：在线目录加载失败时用户不知道该干嘛 → 错误态必须给出路（重试 / 换镜像 / 提示精选仍可用）

网络依赖属于流程，本期明确：拉在线目录依赖 radio-browser API（`all` / `de1` 镜像，失败自动换下一个）；播放依赖电台流直连。两者独立失败、独立提示。设备无权限概念，权限流程不适用。

## 阶段 3 · 页面主任务

```
列表页
  主任务：点一个台开始播放（占满屏幕的列表本身）
  次要：切换来源 tab、收藏/取消收藏（每行 + / ✓）
  低频：筛选（仅在线 tab 头部入口）、加载更多（列表末尾）

筛选页（全屏，仅从在线 tab 进入）
  主任务：选分类并应用（底部通栏[应用]）
  次要：地区、排序
  低频：重置

正在播放页（本期只做支撑流程的最小版）
  主任务：播放/停止 + 音量
  次要：上一台/下一台、进入电台列表
  低频：设置（本期不做，仅保留入口位）
```

## 决策记录（Claude 自行决策，可逐条推翻）

1. **不做设备端文本搜索**。240×320 上中文输入不成立，拼音软键盘性价比低；用「分类 + 地区 + 排序」覆盖找台需求，文本搜索留给以后的 Web 配置页。
2. **codec 对用户不可见**。在线目录请求固定带 `codec in (MP3, AAC)`、`hidebroken=true`、`order=votes`，HLS(m3u8) 流本期不支持也不展示——用户不需要理解「为什么这个台点了没声」。
3. **精选 = 固件内置的已验证直连流**（JSON 打包进 flash，即 2026-09-02 实测可用的那批），兜底「radio-browser 不可达」和「首次启动」两个场景。
4. **筛选条件全部单选**。对应 radio-browser 单个查询参数，固件端查询构造和 UI 状态都最简单；多选是增强项。
5. **分页 20 条/页**，列表末尾点按加载（不做滚动自动加载，触摸屏误触率高、实现复杂）。
6. **收藏上限 50**，写 NVS；满时提示「收藏已满，先删一个」。
7. **上一台/下一台的循环范围 = 当前台所属的列表**（从收藏点的就循环收藏），符合「换台」心智。
8. **tab 记忆**：列表页记住上次停留的 tab；首次启动落在精选。
9. **触控尺寸**：行高 43px、主按钮高 ≥40px、chip 高 30px（320×240 @2.8" ≈ 143PPI，43px ≈ 7.6mm，接近指尖目标下限；chip/迷你条略低于下限，但都是宽目标且误触代价低）。
10. **迷你播放条常驻列表页底部**：选台过程中始终能看到/回到当前播放，防止「迷路」。
11. **横屏 320×240，列表页 tab 左侧竖排**：横屏下顶部再叠一行 tab 会把列表压到 3 行；左侧 60px 竖排 tab 换回完整 4 行，且三个 tab 的触控目标更大（60×57px）。播放页把「电台列表」入口与换台键合并为一排，省出台名区域的高度。
12. **音量用滑动条、Wi-Fi 用常规弧形图标**（用户拍板，2026-09-02，替换最初的「±步进按钮 + 分段格」方案——板子性能/存储充足，无需为省资源牺牲惯用控件）。滑动条：0–100、整行 34px 热区、方形拇指 14×24、无数值文字（靠填充量示意）；对应 LVGL 原生 slider。行首「音量」文字改为喇叭图标（用户拍板），波纹数反映音量：0=静音叉、≤50% 一道、>50% 两道。Wi-Fi 图标：三弧+点，离线态 = 弧线变灰 + 斜杠 + 「离线」文字（灰阶下仅靠图形变化不够醒目，补文字）。

## 实现落地后的偏差记录

阶段 6 实现时，根据 radio-browser 的真实数据和硬件约束做了两处调整：

1. **「地区」改成「语言」**（2026-09-02）。原设计是「全部 / 内地 / 港澳台」，但 API 的 `state`
   字段是混乱的罗马音（`Chekiang` 和 `Zhejiang` 并存、`Dalian` 和 `Shanghai` 与省份混排），
   按它筛选结果不可信。`language` 字段干净得多（chinese 406 / cantonese 9 / english 6），
   且直接对应 API 参数。分类标签也换成了按真实频次挑的：music(144) / news(85) /
   entertainment(33) / information(29) / pop(22) / oldies(18) / traffic(12)。
2. **首版只支持 MP3**。解码器是 libhelix-mp3，AAC/AAC+ 和 HLS 的台会被客户端过滤掉，
   不出现在列表里——这是决策 2「codec 对用户不可见」的自然延伸：与其让用户点了没声，
   不如根本不展示。精选表因此从 8 个减到 7 个（去掉 AAC+ 的 AsiaFM 高清音乐台）。

另外补了设计阶段没覆盖的一环：**Wi-Fi 配网**。首次开机没有凭据，屏幕显示引导页，
设备开热点 `ES3C28P-Radio`，手机连上后在 `192.168.4.1` 填账号密码。
按住 BOOT 键上电可清除凭据重新配网。

### 阶段 8 最终视觉决策

- 首页固定纵向几何，离线/错误只替换状态与动作，不改变音量条的底部位置。
- 顶栏为菜单、当前时间、Wi-Fi；不显示电量和信号数值，呼号只出现在抽屉署名与关于页。
- 台名过长自动滚动；主页控制去除可见外框，但每个触控热区保持至少 44px 高。
- 视觉效果可在单线心电图式流线与 17 根镜像能量条间滑动切换。中心唯一一根由 RMS 响度与低中频托底，左右由真实频谱镜像，并从中心向两侧逐级减弱。
- 视觉数据来自解码后 PCM 的 9 频段 FFT；主页视觉区仅承担音频反馈，不再隐藏额外的页面入口。
- 抽屉只放视觉效果、睡眠定时和设置，避免与设置页重复；标题使用 `Radio OS` 与浅色 `by BI8SYN`。
- 设置承载 Wi-Fi、自动续播、时间格式、亮度、系统更新、诊断与关于。
- 配色为 `#F8F8F5` 暖白背景、`#17171C` 主文字、`#635BFF` 唯一强调色；LCD 继续使用硬件 INVON，禁止交换主题颜色补偿极性。

## 阶段 7 · 产品化视觉与功能补全（2026-09-05）

- 风格：深色中性背景、抬升表面、暖橙单一强调色；强调色只编码主操作、播放中、联网与收藏状态。
- 层级：播放页仍以台名和播停为主任务；设置与发现入口保持次级，未改变已经验收的主流程。
- 触控与反馈：按钮统一圆角和按压态，连续量保留滑块；联网、缓冲、失败、空列表状态继续就地反馈。
- 国内网络：原「精选」升级为 25 个国内优先直连台，原「在线」改名「发现」，避免海外目录成为日常使用的单点依赖。
- 本机配置：新增屏幕选网与密码键盘；热点网页降级为备用入口。
- 配网边界：扫描为空仍提供隐藏网络手动输入；连接失败回到可操作页面，不停在无限等待。
- 设置：新增自动续播、睡眠定时、背光亮度、设备/电池信息，并持久化最后电台与用户偏好。
