# 代码结构与维护约定

Radio OS 保留 ESP-IDF + LVGL 8 的现有实现。界面按职责拆分，不引入页面框架、事件总线或新的动态分配模型；对外仍使用 `main/ui.h`。

## 从哪里开始修改

| 需求 | 入口 |
|---|---|
| 页面切换、主题重建、后台状态通知 | `main/ui.c` |
| 当前电台、列表内切台、自动续播、睡眠到期、暗色时段判断 | `main/app_radio.c` |
| 用户偏好、上次电台的 NVS 兼容读取与保存 | `main/preferences.c` |
| 播放页、抽屉、音量、睡眠显示、息屏遮罩 | `main/ui/ui_player.c` |
| 电台列表、收藏按钮、分页、筛选草稿 | `main/ui/ui_stations.c` |
| 设置、主题色选择弹层 | `main/ui/ui_settings.c` |
| 色板、自动外观与主题设置接口 | `main/ui/ui_theme.c` |
| 本机选网、密码输入、配网引导 | `main/ui/ui_wifi.c` |
| 关于、OTA、诊断、五点触摸检查 | `main/ui/ui_info.c` |
| 公共按钮、标题、信息行、图标 | `main/ui/ui_widgets.c` |
| PCM 频谱的视觉映射和画布缓冲 | `main/ui/ui_visual.c` |
| 启动画面与启动过渡 | `main/ui/ui_boot.c` |

播放解码、Wi-Fi、OTA 验签下载、电台数据和板级驱动仍由原模块负责。`wifi_mgr` 通过回调报告联网/配网状态，不包含 `ui.h`，不决定具体显示哪个页面。

## 状态与任务边界

- **页面对象私有**：控件指针只能在所属 `.c` 文件中保存、更新、清空。跨页面调用使用内部头文件里的函数，不添加 `extern lv_obj_t *`。
- **应用数据单一来源**：`app_radio_state()` 保存当前电台、来源、偏好等不依赖 LVGL 的数据。初始化后，只有 UI 任务或持有 LVGL 锁的入口能读写这份可变状态。
- **后台通知不碰页面**：播放器/OTA/Wi-Fi 回调只写 `ui.c` 的短临界区邮箱。40ms UI tick 消费通知，再执行续播、更新检查和界面刷新。只保留最新状态，不向邮箱保存临时字符串指针或密码。
- **扫描任务用局部结果**：Wi-Fi 扫描在工作任务中执行；拿到 UI 锁后检查页面是否仍可见，再拷贝结果、刷新控件。离开页面后返回的结果不会操作已释放的对象。
- **睡眠使用单调时钟**：应用层处理计时和停止播放，UI 处理倒计时与息屏。取消/重新设定会替换同一个截止时间，没有旧定时器回调残留。

UI 内部 `*_locked` 接口要求调用方已持有 LVGL 锁。公开诊断操作自行加锁，后台回调接口则只投递通知；头文件会说明这些例外。

## 页面生命周期

常规页面在初始化和主题重建时构建；关于、OTA、诊断页面保持按需创建，离开时释放。不要为了拆文件把所有页面都改成常驻。

触摸和串口跳页统一走 `ui_navigate_locked()`，配网引导使用同一个底层 `ui_load_screen_locked()`，避免忘记离开页清理。页面模块提供自己的 `destroy()`：先删父屏幕，再清空本模块句柄。播放页必须先销毁画布对象，再释放频谱 PSRAM 缓冲。

主题重建先切到过渡页，各模块销毁自身页面，再重新构建并恢复当前页面与设置滚动位置。应用数据不随页面销毁。启动动画、配网输入、触摸测试和息屏期间延迟重建；异步重建真正执行时再次检查当前页面，避免覆盖用户刚进行的跳转。

装饰性子对象（例如色点、十字线）也要显式清除 `LV_OBJ_FLAG_CLICKABLE`：父对象不可点击不会自动传递给子对象，否则点中装饰中心可能无法触发按钮或采样区。

新增页面需要补齐：页面 ID/查询、构建入口、导航准备、销毁路径、主题切换后的恢复策略，以及串口/触摸回归。无需把该页面的每个控件加入 `ui.c`。

## 持久化兼容性

`preferences.c` 保留旧版本的 `radio` 命名空间、键名、整数类型及 `station_t` blob 格式。界面结构重构不能顺便重命名这些键。后续如果修改 `station_t` 存储布局，应单独设计迁移，不依赖结构体大小恰好相同。

Wi-Fi 凭据、收藏和播放器音量仍由各自服务模块保存。公共设置行通过显式输出参数返回值标签，不能依赖中文标题或子控件序号绑定业务状态。

## 验证

- `tests/host/run.sh`：编译真实应用/偏好模块，替换硬件边界；覆盖切台环绕、空收藏退回、筛选来源、睡眠取消/替换/一次到期、续播与更新检查、全部 24×24×24 暗色时段组合、旧设置键与边界值。开启地址/未定义行为检查，CI 同步执行。
- 固件构建与实机 `selftest`：检查资源余量和整机健康，但不替代交互验证。
- `tests/device/`：可选开发探针和串口回归，见该目录 README。验证页面显示、真实 LVGL 输入链路、反复主题切换、后台扫描、播放和内存回收。

结构重构不改变版本号、OTA 签名或线上发布。正式发布仍遵循 `docs/release-process.md`。

本次重构的验证范围、实机数据与交付状态见 [refactor-validation.md](refactor-validation.md)。

## 随机换台

播放页顶部随机按钮使用独立 44×36 点击区，位于时钟与 Wi-Fi 之间；选中态由
`app_radio_state.shuffle` 驱动，主题重建后恢复。时钟与睡眠倒计时上下排列。
开关只改变模式，不触发播放；`radio/shuffle` 保存偏好，旧配置默认关闭。

`app_radio_step_station()` 在随机模式下按当前播放来源抽样，排除当前流地址。
从目录选台时冻结筛选条件，浏览其他列表不改变播放池；收藏池实时反映收藏变更。
候选为空时不重连，空来源仍沿用原来的推荐回退。上一台回退最多 12 条会话历史，
历史使用电台副本，避免列表变动使引用失效；直接选台、切换模式和重启会清空历史。
重启后的目录播放来源使用默认全部范围（筛选条件与历史均不持久化）。
